# Building Blocks

Minimal templates plus the rules for each block. The running example is an e-commerce
**Catalog** context with a `Product` aggregate. Adapt the names to the project's ubiquitous
language. PHP 8.4+ features (`public private(set)`) and PHP 8.5 features (`#[\NoDiscard]`) are
used only when the installed PHP allows them.

Default layout per bounded context:

```
src/
├── Shared/{Domain,Application,Infrastructure}
└── Catalog/
    ├── Domain/Model/Product/      Product, ProductId, ProductPrice, events, ProductRepository, domain services
    ├── Application/Service/Product/  commands, application services, DTOs
    └── Infrastructure/            Persistence/Doctrine (repository, mapping, types), Delivery (API, console), Messaging
```

---

## Entity + Aggregate Root

- Identity that never changes. Generated by the app (UUID v7), not by the DB, so events can carry
  the id before `flush()`.
- The root is the only door into the aggregate. Children (e.g. `Review`) are created only by the
  root.
- Methods are named in the ubiquitous language, guard the invariants and return `void`.
- `final` is fine: Doctrine uses native lazy objects on PHP 8.4+.

```php
namespace App\Catalog\Domain\Model\Product;

final class Product
{
    public private(set) ProductStatus $status;
    public private(set) int $reviewCount = 0;
    public private(set) int $ratingSum = 0;
    private Collection $reviews;
    private int $version = 1; // optimistic lock

    public function __construct(
        public private(set) ProductId $id,
        public private(set) string $title,
        public private(set) ProductPrice $price,
    ) {
        if (trim($title) === '' || mb_strlen($title) > 100) {
            throw new \InvalidArgumentException('Title must be 1 to 100 characters.');
        }
        $this->status = ProductStatus::Draft;
        $this->reviews = new ArrayCollection();
    }

    public function publish(): void
    {
        if ($this->status !== ProductStatus::Draft) {
            throw new \DomainException('Only a draft product can be published.');
        }
        $this->status = ProductStatus::Published;

        DomainEventPublisher::instance()->publish(new ProductPublished(
            productId: (string) $this->id,
            title: $this->title,
        ));
    }

    public function addReview(string $customerId, Rating $rating, string $comment): void
    {
        if ($this->status !== ProductStatus::Published) {
            throw new \DomainException('Only a published product can be reviewed.');
        }
        $this->reviews->add(new Review($this, $customerId, $rating->value, $comment));
        $this->reviewCount++;
        $this->ratingSum += $rating->value;
    }
}
```

Keep aggregates small. Reference other aggregates by id. Use a counter or sum (with an
optimistic-lock version) instead of loading large child collections for derived values.

## Value Object

- No identity, immutable (`final readonly`), validates itself in the constructor.
- "Changes" return a new instance (`#[\NoDiscard]` on PHP 8.5).
- Money is an integer in minor units plus a currency, never a float.

```php
final readonly class ProductPrice
{
    public function __construct(public int $amount, public Currency $currency)
    {
        if ($amount < 0) {
            throw new \InvalidArgumentException('Price can not be negative.');
        }
    }

    #[\NoDiscard]
    public function withAmount(int $amount): self
    {
        return new self($amount, $this->currency);
    }
}
```

## Domain Service

- Only for a business rule that doesn't fit one entity/VO (it needs other aggregates or outside
  data). First ask: can the entity do it?
- Stateless, in the Domain, depends on ports only, and named in the domain language (not
  `ProductDomainService`).
- Back uniqueness-style rules with a DB constraint as the safety net (two requests can race).

```php
final readonly class UniqueProductTitle
{
    public function __construct(private ProductRepository $productRepository) {}

    public function check(string $title): void
    {
        if ($this->productRepository->existsWithTitle($title)) {
            throw new ProductTitleAlreadyUsed("A product named \"$title\" already exists.");
        }
    }
}
```

## Domain Event

- A past-tense fact, `final readonly`, primitives only (serializable), created with named
  arguments.
- Raised inside the Domain model, never from controllers or infrastructure.

```php
namespace App\Shared\Domain\Event;

abstract readonly class CommonEvent
{
    public \DateTimeImmutable $occurredOn;

    public function __construct(?\DateTimeImmutable $occurredOn = null)
    {
        $this->occurredOn = $occurredOn ?? new \DateTimeImmutable();
    }
}

interface DomainEventSubscriber
{
    public function handle(CommonEvent $event): void;
    public function isSubscribedTo(CommonEvent $event): bool;
}

final class DomainEventPublisher
{
    private static ?self $instance = null;
    /** @var array<int, DomainEventSubscriber> */
    private array $subscribers = [];
    private int $nextId = 0;

    public static function instance(): self
    {
        return self::$instance ??= new self();
    }

    public function subscribe(DomainEventSubscriber $subscriber): int
    {
        $this->subscribers[$this->nextId] = $subscriber;

        return $this->nextId++;
    }

    public function unsubscribe(int $id): void
    {
        unset($this->subscribers[$id]);
    }

    public function publish(CommonEvent $event): void
    {
        foreach ($this->subscribers as $subscriber) {
            if ($subscriber->isSubscribedTo($event)) {
                $subscriber->handle($event);
            }
        }
    }
}
```

If the project instead records events on the aggregate (`$this->recordThat()` + `pullEvents()`),
follow that. The after-commit dispatch rule still applies.

## Repository (port)

- An interface in the Domain, one per aggregate root, collection-like. No `flush()`, no
  `save()` that commits.
- `nextIdentity()` lives here, so ids are known before persistence.

```php
interface ProductRepository
{
    public function nextIdentity(): ProductId;
    public function add(Product $product): void;
    public function productOfId(ProductId $id): ?Product;
    public function existsWithTitle(string $title): bool;
}
```

Write an `InMemoryProductRepository` for application-service tests.

## Command / Query

- `final readonly`, primitives only, no logic, no `#[Assert]`.
- A Command changes state; a Query reads and returns a DTO. A create command may return the new id.

```php
final readonly class CreateProductCommand
{
    public function __construct(
        public string $title,
        public int $priceAmount,
        public string $currency,
    ) {}
}
```

## Application Service

- One use case, one public `execute()`, receives a Command/Query.
- Load → call the domain → add/save → return a DTO, an id or nothing. Never the entity.
- No business `if`s: if you see one, move it into the Domain.
- The constructor takes only Domain/Application classes and ports.
- The transaction is wrapped by the `TransactionalSession` port.

```php
namespace App\Shared\Application;

interface TransactionalSession
{
    public function executeAtomically(callable $operation): mixed;
}
```

```php
final readonly class CreateProductService
{
    public function __construct(
        private ProductRepository $productRepository,
        private UniqueProductTitle $uniqueProductTitle,
        private TransactionalSession $session,
    ) {}

    public function execute(CreateProductCommand $command): string
    {
        return $this->session->executeAtomically(function () use ($command) {
            $this->uniqueProductTitle->check($command->title);

            $product = new Product(
                id: $this->productRepository->nextIdentity(),
                title: $command->title,
                price: new ProductPrice($command->priceAmount, Currency::fromCode($command->currency)),
            );
            $this->productRepository->add($product);

            return (string) $product->id;
        });
    }
}
```

## Tests

- **Domain:** construct objects directly, assert the state or the exception. No kernel, no DB.
  One test per rule, including the failure path.
- **Application:** in-memory repository + a pass-through `TransactionalSession` (just calls the
  closure).
- **Infrastructure:** a few integration tests (the mapping round-trip, the unique constraint, the
  optimistic lock) with the kernel and a test DB.
